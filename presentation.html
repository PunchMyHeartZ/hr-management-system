ENTITY DESIGN 1/2

เอนทิตี้หลัก — ข้อมูลองค์กรและการลา

ความสัมพันธ์แบบ One-to-Many (1 ──∞)

departments

  • PK department_id SERIAL
  • department_name VARCHAR UNIQUE
  • department_code VARCHAR UNIQUE
1 ──∞

employees

  • PK employee_id SERIAL
  • first/last_name, email UNIQUE
  • position, phone, hire_date
  • FK department_id → departments
  • salary NUMERIC(12,2) ≥ 0
  • status CHECK (active/inactive/terminated)
  • annual_leave_quota INT
1 ──∞

leave_requests

  • PK leave_id SERIAL
  • FK employee_id → employees
  • leave_type CHECK (annual/sick/personal/unpaid)
  • start_date, end_date (CHECK end ≥ start)
  • status CHECK (pending/approved/rejected)

FK แผนกใช้ ON DELETE RESTRICT (กันลบแผนกที่มีคน) • FK พนักงานใช้ ON DELETE CASCADE (ลบคนแล้วข้อมูลย่อยหายตาม)

ENTITY DESIGN 2/2

เอนทิตี้เงินเดือนและผู้ใช้งาน

ทุกตารางผูกกับ employees ด้วย FK (CASCADE)

attendance

  • PK attendance_id
  • FK employee_id
  • work_date, check_in, check_out
  • ot_hours NUMERIC(5,2)
  • UNIQUE (employee_id, work_date)

bonuses

  • PK bonus_id
  • FK employee_id
  • bonus_year INT, amount ≥ 0
  • UNIQUE (employee_id, bonus_year)

payroll_records

  • PK payroll_id
  • FK employee_id
  • pay_period (year, month)
  • base_salary, ot_hours, ot_pay
  • bonus, sso, tax, net_pay
  • UNIQUE (employee_id, ปี, เดือน)

users

  • PK user_id
  • username / email UNIQUE
  • password_hash (bcrypt), full_name
  • role CHECK (hr / executive / employee)
  • FK employee_id → employees (1─1, SET NULL)
ENTITY DESIGN 3/3

เอนทิตี้โมดูลเสริม v3 — HR ครบวงจร

ประกาศ • ประกวดผลงาน • รับสมัครงาน (เพิ่ม 5 ตาราง รวมเป็น 12 ตาราง)

announcements

  • PK announcement_id
  • title, body
  • FK created_by → users (SET NULL)
  • created_at

reviews

  • PK review_id
  • FK employee_id → employees
  • period_year, reviewer_name
  • overall_score, strengths, improvements
  • UNIQUE (employee_id, ปี)

review_goals

  • PK goal_id
  • FK review_id → reviews (CASCADE)
  • title, weight, score

positions

  • PK position_id
  • title, headcount, status (open)
  • FK department_id → departments (SET NULL)

applicants

  • PK applicant_id
  • FK position_id → positions (CASCADE)
  • full_name, email, phone
  • status (applied/…), notes

reviews 1 ──∞ review_goals (เป้าหมายถ่วงน้ำหนักคะแนน) • positions 1 ──∞ applicants (ผู้สมัครต่อตำแหน่งที่เปิดรับ)

DDL — pgAdmin

สร้างตารางด้วย DDL Script

รันผ่าน pgAdmin Query Tool — 5 ไฟล์ตามลำดับการพัฒนา (Migrations) • มี Prisma schema สะท้อนโครงสร้างเดียวกัน

-- ตัวอย่างจาก schema.sql (ตาราง employees) CREATE TABLE employees ( employee_id SERIAL PRIMARY KEY, first_name VARCHAR(100) NOT NULL, email VARCHAR(255) NOT NULL UNIQUE, department_id INT NOT NULL REFERENCES departments(department_id) ON DELETE RESTRICT, salary NUMERIC(12,2) NOT NULL CHECK (salary >= 0), status VARCHAR(20) DEFAULT 'active' CHECK (status IN ('active','inactive','terminated')), annual_leave_quota INT NOT NULL DEFAULT 10 ); CREATE INDEX idx_employees_department ON employees(department_id);

5migration_v3.sqlannouncements, reviews, review_goals, positions, applicants

PAYROLL ENGINE

สูตรคำนวณเงินเดือน (โดยประมาณ)

อ้างอิงหลักเกณฑ์ไทย — อยู่ใน backend/src/payroll.ts

ค่าล่วงเวลา (OT)OT = ชม.OT × (เงินเดือน ÷ 30 ÷ 8) × 1.5
ชม.OT = ชั่วโมงทำงาน − 8 (หักพักเที่ยง 1 ชม.)
ประกันสังคม (SSO)SSO = min(เงินเดือน × 5%, 750 บาท/เดือน)
ภาษีหัก ณ ที่จ่ายขั้นบันได 0–35% จากรายได้ต่อปี
หัก: ค่าใช้จ่าย 50% (สูงสุดแสน) • ค่าลดหย่อน 60,000 • SSO
ภาษีโบนัสหักครั้งเดียวเดือนที่จ่าย ที่อัตราขั้นสูง (marginal rate) ของพนักงาน
เงินสุทธิ = (เงินเดือน + ค่า OT + โบนัส) − ประกันสังคม − ภาษีหัก ณ ที่จ่าย
